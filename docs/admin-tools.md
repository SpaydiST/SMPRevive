# Администрирование SMPRevive 1.2.0

Все новые команды и меню требуют право `smprevive.admin`, которое по умолчанию есть у операторов сервера.

| Команда | Назначение |
| --- | --- |
| `/revive status <игрок или UUID>` | Сердца, статус жизни, аллергия, предмет и цена воскрешения, ожидающее появление |
| `/revive menu <игрок или UUID>` | Отдельное меню администратора для просмотра статуса, истории и диагностики |
| `/revive history [игрок или UUID или all] [страница]` | Последние операции, 10 записей на страницу |
| `/revive diagnostics` | TPS, задачи плагина, алтари, незавершённые операции восстановления, записи файлов и время работы |
| `/revive difficulty <easy или normal или hard>` | Применить профиль стоимости и резервного радиуса события |
| `/event preview` | Показать мир, участников, границу и резервный радиус без запуска события; выполнять в игре |
| `/event status` | Текущая фаза и количество участников |
| `/event stop` | Остановить событие и восстановить состояние игроков и границы |

В игре `status` и `menu` без имени показывают самого администратора. Из консоли укажите игрока или UUID. Неизвестные имена не создают новые записи игроков.

Меню предназначено для просмотра: в нём нельзя перемещать предметы. Баланс означает число предметов нужного типа в основном инвентаре смотрящего администратора. Голова игрока нужна отдельно. Окончательно доступность воскрешения, оплату и безопасное место проверяет алтарь. Данные обновляются кнопкой часов, без повторяющейся задачи.

## Профили сложности

| Профиль | Предметов для воскрешения | Резервный радиус события |
| --- | ---: | ---: |
| easy | 80 | 250 |
| normal | 160 | 500 |
| hard | 320 | 1000 |

Значения настраиваются в `admin-presets` файла `config.yml`. Установка новой версии сама не применяет профиль. Радиус используется как резервный: RandomSpawnPlus может переопределить его для мира. Во время активного события менять профиль нельзя. При применении профиля открытые меню закрываются через существующий механизм возврата предметов.

## История

История хранится отдельно в `admin-history.log`, чтобы не менять журнал возврата платежей. Записываются завершённые и отменённые воскрешения, выдача предметов, установка сердец, аллергия, смена профиля, перезагрузка и команды запуска/остановки события. Для воскрешения показывается количество оплаченных предметов; административное воскрешение без оплаты имеет значение 0.

В памяти доступны последние 1000 записей; файл ротируется при достижении 512 КиБ и сохраняет один предыдущий файл `.1`. Фильтр игрока использует UUID получателя операции. `CANCELLED_REFUND_REQUESTED` означает отмену с запросом возврата: это не подтверждение завершённого возврата, поскольку его обеспечивает отдельный журнал восстановления.

При ошибке записи операция в игре не отменяется из-за истории. Запись остаётся в памяти, а предупреждение о неполной сохранности остаётся до конца текущего запуска, даже если следующие записи удалось сохранить. Такие записи могут исчезнуть при перезапуске; проверьте права доступа и место на диске.

## Диагностика и оптимизация

`players-save`, `altar-sync`, `event-tick` показывают количество вызовов, среднее и максимальное время с запуска. TPS относится ко всему серверу. Для сравнения выполните `/revive diagnostics` при одинаковой нагрузке до и после игрового сценария. Замеры состояния события и алтарей появляются после соответствующих действий.

Неизменившееся состояние игроков повторно не записывается. Изменения сохраняются синхронно через временный файл и замену основного; после ошибки запись можно повторить, включая откат предыдущего состояния. Удаление файла и обычные внешние изменения его размера/времени обнаруживаются.

Шаблоны предметов копируются перед использованием и сбрасываются при перезагрузке настроек. Казино обновляет слот только при смене материала. Отображения алтарей проверяются через кэш живых сущностей; ссылки удаляются при выгрузке чанка. Сохранена периодическая проверка отсутствующих отображений, а начальная синхронизация не загружает неактивные чанки.

Для установки остановите сервер, замените предыдущий JAR на `SMPRevive-1.2.0.jar` и запустите сервер. Не оставляйте две версии плагина одновременно.
