# Оптимизация SMPRevive 1.3.1

Выполнена первая предложенная группа оптимизаций: сохранение состояния, очередь возвратов, офлайн-квитанции, полёты голов, проверка аллергии и поиск алтарей. Версия предназначена для Paper 26.3 и Java 25. Новых production-зависимостей нет.

## Изменения

| Область | Что изменилось |
| --- | --- |
| Состояние игроков | Неизменившееся состояние повторно не преобразуется в YAML. Проверка файла на диске и атомарная запись при изменениях сохранены |
| Записи выдачи | Содержимое предмета кодируется один раз на запись; изменяемые поля владения сохраняются заново |
| Очередь возвратов | Записи выбираются по сроку следующей попытки. Головы с ещё не наступившим сроком не обходятся каждые полсекунды |
| Ожидание | Вход игрока, движение, смена мира, освобождение места и загрузка нужного чанка могут приблизить следующую попытку. Повторные сигналы от одного игрока объединяются на следующий тик, а сигналы мира — до прохода очереди. За проход пробуждается не более 64 записей по всем мирам; крупные миры обрабатываются по очереди |
| Офлайн-квитанции | Несколько квитанций одного владельца читаются из одного playerdata за проход. При недоступном файле повтор откладывается на 1, 2, 5, затем 15 секунд; вход владельца сбрасывает эту задержку |
| Полёты голов | Один общий обработчик анимации; одновременно не более 16 полётов. Ошибка одной анимации оставляет её предмет в очереди и позволяет продолжать остальные |
| Аллергия | Периодическая проверка посещает только находящихся онлайн игроков с аллергией. Проверка их инвентаря по-прежнему выполняется раз в полсекунды |
| Алтари | Координаты разобраны заранее; проверка регистрации использует индекс, а загрузка чанка получает только относящиеся к нему алтари |
| Диагностика | Добавлены счётчики сериализаций, посещений очереди, чтений playerdata и запусков полётов в административную диагностику |

## Правила возврата

Голова в блоке или рамке сохраняет срок возврата через 10 реальных минут. Получатель — ближайший подходящий живой игрок в том же мире. Если игроков нет или у ближайшего нет места, выдача остаётся в сохранённой очереди. Полёт длится около 3 секунд при нормальной скорости сервера; занятый лимит полётов откладывает старт следующей головы.

Сердца продолжают складываться в стаки. Сохранены квитанции списания и получения, атомарное подтверждение группы выдач, обработка окончательной отмены установки, списание головы в creative и защита от повторного обнаружения уже выданной рамки. Анимация не владеет предметом: после прерывания возврат восстанавливается из записи.

## Ограничение работы за проход

Сигналы конкретного игрока или чанка посещают до 64 записей; остальные сохраняют обычный срок повтора. Очередь выбирает до 64 готовых записей, выполняет до 8 результативных попыток и проверяет бюджет 3 мс между операциями. Обработка объединённых сигналов мира входит в измерение этого времени. Необработанные записи возвращаются в расписание с сохранением их очередности относительно более поздней работы.

Это мягкий бюджет. Одна синхронная запись или чтение медленного диска может занять больше 3 мс. Подтверждение группы списания также остаётся общей атомарной операцией. Критические сохранения не перенесены в фон; лимит не гарантирует максимальную длительность любого тика.

## Административная диагностика

Команда `/revive diagnostics` и соответствующая кнопка админ-меню требуют `smprevive.admin` (по умолчанию OP). Счётчики накопительные с запуска плагина и появляются после первой соответствующей операции.

| Счётчик | Значение |
| --- | --- |
| `players-serializations` | Повторные преобразования изменившегося состояния игроков в YAML |
| `queue-visited` | Записи, реально посещённые обработчиком очереди |
| `queue-budget-yields` | Проходы, оставившие готовые записи на следующую попытку |
| `world-wake-visits` | Посещения записей при обработке объединённых сигналов мира; не более 64 за проход |
| `offline-receipt-checks` | Групповые попытки проверки офлайн-квитанций |
| `offline-receipt-files` | Выбранные файлы playerdata для чтения, включая неуспешный разбор |
| `offline-receipt-bytes` | Сумма размеров этих сжатых файлов; не объём физического чтения с диска |
| `flights-started` | Начатые анимации голов |
| `allergy-player-visits` | Посещения онлайн-игроков с аллергией |

Времена `protected-queue`, `offline-receipts`, `head-flights` и `allergy-scan` показывают среднее и максимум измеренных вызовов. Это не показатели TPS и не процентили задержек.

## Обновление и интеграции

Установочный файл — `target/SMPRevive-1.3.1.jar`. Обычная замена JAR при остановленном сервере сохраняет существующие конфигурацию и данные. Формат очереди совместим с 1.3.0. Версия API в проекте — `26.3.build.134-beta`; результаты отдельного запуска Paper приведены в отчёте проверки.

Для интеграций сохранены существующие публичные методы DataManager. Замена списка `altars` через конфигурацию и изменение его размера обнаруживаются автоматически. Если сторонний плагин меняет исходный объект списка на месте, сохраняя его размер, после этого он должен вызвать `getDataManager().reloadAltarIndex()`.

Индексы алтарей хранят имена миров, а не объекты World. Мир разрешается при запросе; индекс не загружает чанки. Периодическая общая сверка визуальных элементов алтарей остаётся раз в 5 секунд.
